# Product

<!-- impeccable:product-schema 1 -->

## Platform

web and desktop

## Users

Rowake is for developers and operators who need to inspect a relational database while building, debugging, or operating an application.

## Product Purpose

Rowake is a self-hosted relational database viewer for inspecting connections, schemas, tables, rows, indexes, relationships, and bounded query results.

Success means a user can start Rowake, connect to a supported database, and inspect its data and structure without additional services.

## Operating Context

- Rowake runs as a single Go binary with an embedded dependency-free browser interface.
- It can open in a local desktop/browser workflow or run as a hosted service.
- Users inspect databases during development and operations, typically in a local or trusted environment.
- Normal builds include SQLite, PostgreSQL, and MySQL/MariaDB drivers without separate editions or build tags.

## Capabilities and Constraints

- The current MVP opens local SQLite files and PostgreSQL databases in read-only mode and supports connection selection, catalog browsing, loaded-row search/filter/sort, table structure and index inspection, foreign-key topology, and bounded SQL query results.
- Rowake starts without fabricated connections or records.
- The Wails desktop app persists local SQLite connection definitions on the device. PostgreSQL credentials and browser/server connections live only for the current process.
- PostgreSQL setup can enumerate databases the supplied account may connect to, then connect to the selected database and browse its non-system schemas.
- Table previews, query results, connection pools, and statement execution must remain bounded.
- Read-only database credentials are the primary safety boundary; application-level query guards are defense in depth.
- Persisted connection credentials, schema mutation, arbitrary writes, multi-user authorization, saved queries, query-history persistence, imports, exports, data diffing, SSH tunnels, and cloud-specific authentication are outside the current scope.
- The MySQL/MariaDB driver is bundled for a future adapter, but MySQL/MariaDB is not available in the current connection flow.
- Row editing is planned after the read-only MVP. UI actions must remain capability-gated so write support can be introduced without changing the browsing model or implying access the active connection does not have.

## Brand Commitments

- The product name is Rowake.
- Product language should be direct, precise, and honest about capabilities, limits, and safety.
- The current interface uses a compact dark workbench, dense data grids, and a relationship canvas.

## Implementation

- The current product interface is implemented in `webembed/dist/`.
- Architecture and distribution constraints are documented in `docs/ARCHITECTURE.md` and `docs/DRIVERS.md`.
- The service boundary and current product data model are defined in `internal/app/types.go`.
- Browser and Wails desktop launches share the loopback server in `internal/launch/`.
- The deterministic SQLite fixture is generated by `cmd/rowake-testdb` and committed at `testdata/rowake-test.sqlite`.
- No Rowake software license has been selected.

## Product Principles

1. Make database facts easy to find and understand without guessing.
2. Keep the interface focused on rows, structure, relationships, and query results.
3. Stay lightweight to run, self-host, distribute, and maintain.
4. Bound expensive work and communicate safety limits precisely.
5. Provide one coherent product while expanding database support deliberately over time.
